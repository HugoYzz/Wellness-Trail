# 安全检查清单与结论

检查日期：2026-09-13
适用版本：本仓库 `main` 分支当前版本

## 结论

**允许用于单机或可信局域网内的个人使用；不批准直接暴露到公网。**

主要原因是公网场景尚缺 HTTPS 终止、持久化服务端会话、独立 CSRF 防护和自动化主机文件权限检查。`assets/` 可能含真实健康资料，已作为本地目录忽略；不要使用强制添加把它写入 Git 历史。

## 已检查并具备

| 检查项 | 状态 | 证据/说明 |
|---|---|---|
| 默认网络边界 | 通过 | `start.ps1` 默认绑定 `127.0.0.1`；局域网需显式 `-Lan`。 |
| 业务 API 鉴权 | 通过 | 除健康检查与登录流程外，`/api/*` 统一校验会话。 |
| PIN 存储 | 通过 | PBKDF2-SHA256、随机盐、310,000 次迭代，不保存明文。 |
| 登录防爆破 | 通过 | 单客户端 5 次失败后进入 5 分钟窗口限流。 |
| Cookie 基线 | 条件通过 | `HttpOnly`、`SameSite=Strict`、限定根路径；本地 HTTP 下 `Secure=false`。 |
| 密钥管理 | 通过 | `.env` 被忽略，API Key 仅由后端读取；示例文件不含密钥。 |
| 运行数据隔离 | 通过 | `data/`、`assets/`、SQLite、测试数据库、报告和工具缓存均被忽略。 |
| 数据恢复安全 | 通过 | 先在隔离数据库执行恢复演练；真实恢复需显式确认并在事务中进行。 |
| SSE 幂等 | 通过 | `request_id` 唯一约束、事件持久化、`Last-Event-ID` 补发；单测与浏览器测试覆盖。 |
| CORS | 通过（本地） | 仅允许开发前端的 localhost/127.0.0.1 来源并携带凭据。 |
| CI 最小权限 | 通过 | Actions 仅授予 `contents: read`，测试使用 Mock 和临时数据库。 |

## 尚未满足的公网条件

- [ ] 通过 Caddy、Nginx 等终止 HTTPS，并把会话 Cookie 改为 `Secure=true`。
- [ ] 将会话状态迁移到可持久化、可撤销且带轮换策略的存储；当前后端重启会要求重新登录。
- [ ] 增加独立 CSRF Token 或严格的反向代理 Origin 校验；当前主要依赖 `SameSite=Strict`。
- [ ] 对数据库、备份和日志执行操作系统级最小权限及加密盘检查。
- [ ] 为公网访问增加审计日志、告警、备份保留/销毁策略与灾难恢复目标。
- [ ] 公开仓库前复核完整 Git 历史，确认从未强制提交 `assets/` 或其他个人资料；若存在则先做历史清理。
- [ ] 持续运行依赖漏洞扫描并建立修复时限。

## 每次发布前

- [ ] `git status` 中没有 `.env`、数据库、备份、浏览器配置或测试报告。
- [ ] 搜索提交内容，确认没有 API Key、Cookie、PIN、手机号、身份证号和健康身份信息。
- [ ] 运行后端单测、前端单测、生产构建和 Playwright SSE 恢复测试。
- [ ] 用最新导出完成一次隔离恢复演练，并记录对象数量与告警。
- [ ] 若启用云端 Provider，确认用户已知晓健康上下文会离开本机。
