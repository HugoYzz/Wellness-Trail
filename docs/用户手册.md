# 康迹用户手册

## 1. 首次使用

运行根目录的 `./start.ps1`，然后打开 `http://localhost:5173`。首次进入会要求创建 6–12 位数字 PIN；PIN 哈希保存在本地数据库，原始 PIN 不会写入配置文件。服务重启后需要重新登录。

## 2. 日常记录

在“对话”页直接描述事实即可，例如：

- `今早空腹 106.5 kg，昨晚 00:30 入睡。`
- `今天走了 8200 步，游泳 45 分钟。`
- `晚饭后喝了 1 杯奶茶，夜里没有饿。`

打开对话页不会创建空会话；当天第一次真正发送消息时才建会话。AI 返回的记录卡不会自动入账，请核对日期、时段、数值和单位后点击确认。

## 3. 纠错与历史修改

进入“时间线”，找到记录并点击“修改”。保存后原记录会被更新，今日计划和相关页面会重新加载。若记录完全无效，可删除后重新录入。对 AI 的文字回复不能直接改写，但由回复生成的结构化健康记录可以纠错。

## 4. 今日计划与洞察

顶部显示今日进度和下一项；对话页右侧是完整计划。首次生成后先确认，再逐项记录、跳过或恢复。身体不适时可将运动改为休息。

“洞察”页展示趋势、目标差距与建议，并标注证据覆盖度。建议仅用于自我观察，不替代诊断；出现胸痛、呼吸困难、意识异常等急症信号时应立即联系急救或医生。

## 5. AI Provider 与 RAG

在“设置”中可以查看可用 Provider、连接状态、能力与评测结果。推荐先使用本地 Ollama；本地 Mock 适合离线验证流程，不用于真实健康建议。选择云端 Provider 前必须明确允许发送健康上下文，并自行确认服务商的数据政策。

RAG 默认保留 FTS5 关键词检索；启用 Ollama Embedding 与 Qdrant 后可重建向量索引。索引失败不会阻断基础检索。

## 6. Token 与费用

费用卡区分模型返回的实测 Token、按文本估算的历史 Token 和仍未知的旧记录。只有配置了对应价格的云端模型才显示费用估算；本地模型显示为本地运行，不把硬件、电费折算为 API 成本。

## 7. 备份、演练与恢复

建议每周复盘后导出一次 JSON，并保存到非系统盘或加密存储：

1. 点击“导出完整 JSON 备份”。
2. 重新选择该文件，系统先在临时 SQLite 中完整恢复并核对集合数量。
3. 只有演练通过后才会出现真实恢复操作。
4. 真实恢复会替换当前数据；执行前保留最新导出和另一份离线副本。

## 8. 常见问题

- 页面提示后端不可用：确认 `start.ps1` 已运行，并访问 `http://127.0.0.1:8001/api/health`。
- PIN 登录失效：后端重启会清空内存会话，重新输入 PIN 即可。
- AI 无响应：在设置页测试 Provider；云端模型检查 `.env` 的密钥，本地模型检查 Ollama 是否运行且模型已下载。
- 消息流中断：前端会自动重连并从最后事件继续；不要连续重复点击发送。相同请求由后端幂等保护。
- 向量 RAG 不可用：仍可继续使用 FTS5；按部署文档检查 Ollama Embedding 与本地索引目录。
